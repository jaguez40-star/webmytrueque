## 1. Contexto del proyecto

### 1.1 Qué es el producto

**MyTrueque.com** es un marketplace P2P de compraventa de archivos entre dos personas
(un vendedor y un comprador), con **custodia (escrow) del archivo** en el servidor y
**pago fuera de la plataforma**. Esta tarea construye únicamente la **página principal
pública** (landing + acceso), que explica el modelo y contiene el login / registro.

Reglas de negocio que el copy de la página comunica (no inventar copy nuevo, el texto
literal está en la Sección 5 de este plan):

- Relación **1 a 1**: el vendedor comparte un archivo con **un** comprador identificado por
  su **@usuario** (ej. `@trq-9k2f`), asignado por el sistema al registrarse.
- El **archivo** pasa por los servidores (custodia cifrada) **solo mientras la orden vive**;
  al confirmarse la descarga se **purga**. Órdenes sin cerrar se purgan a los 30 días.
- El **dinero nunca** pasa por la plataforma: transferencia directa comprador → vendedor.
- Con comprobante cargado, si el vendedor no libera en **24 h**, la plataforma habilita
  la descarga.
- Estados de la orden: `EN CUSTODIA` → `EN INSPECCIÓN` → `PAGO ENVIADO` → `LIBERADO` →
  `DESCARGADO` → `PURGADO`.

### 1.4 Convenciones de código a respetar

- **Idioma**: todo el copy visible en **español** (con tildes correctas). Nombres de
  variables, funciones, tipos y archivos en **inglés**. Comentarios en español.
- **Componentes**: un componente por carpeta, con `NombreComponente.tsx` +
  `NombreComponente.module.scss` + `index.ts` que reexporta.
- **Estilos**: **CSS Modules con Sass** (`*.module.scss`). **Prohibidos los estilos inline**
  (el prototipo los usa solo por limitación de la herramienta de diseño).
  Los valores de color, tipografía y espaciado se consumen **siempre** desde los tokens
  definidos en `src/styles/_tokens.scss` (variables CSS), nunca hardcodeados en el módulo.
- **Sass moderno**: usar `@use`, **nunca** `@import` (está deprecado y emite warnings).
- **Tipado**: `strict: true`. Prohibido `any`. Props tipadas con `interface`.
- **Exports**: componentes con `export function NombreComponente()`, no `export default`.

```json
    "test": "vitest run",
    "test:watch": "vitest"
```

> typecheck de `src/` **y** de `vite.config.ts` a la vez. No usar `tsc --noEmit` a secas:

**(b)** Dependencias de runtime — ejecutar **exactamente** este comando (sin versiones:

### 5.3 `vite.config.ts` — reemplazar el contenido completo

> `import.meta.url` en vez de `__dirname`: `tsconfig.node.json` compila este archivo como

> importan `describe/it/expect` explícitamente y así no hace falta tocar los `types` del

```ts
/// <reference types="vitest/config" />
import { fileURLToPath, URL } from 'node:url'
import react from '@vitejs/plugin-react'
import { defineConfig } from 'vite'

export default defineConfig({
  plugins: [react()],
  resolve: {
    alias: {
      '@': fileURLToPath(new URL('./src', import.meta.url)),
    },
  },
  server: {
    port: 5173,
  },
  test: {
    environment: 'jsdom',
    setupFiles: ['./src/test/setup.ts'],
    css: true,
  },
})
```

### 5.18 `src/shared/components/TextField/TextField.tsx` — crear

Campo de formulario con etiqueta, acción opcional a la derecha de la etiqueta
(el "¿La olvidaste?" del login) y mensaje de error. `react-hook-form` registra el input
por referencia: en **React 19 `ref` es una prop normal**, así que se recibe con
`ComponentPropsWithRef` y no hace falta `forwardRef` (H8; verificado con `tsc` en TS 6).

```tsx
import { useId } from 'react'
import type { ComponentPropsWithRef, ReactNode } from 'react'
import styles from './TextField.module.scss'

interface TextFieldProps extends ComponentPropsWithRef<'input'> {
  label: string
  /** Nodo opcional alineado a la derecha de la etiqueta (ej. "¿La olvidaste?"). */
  labelAction?: ReactNode
  error?: string
}

export function TextField({ label, labelAction, error, id, ref, ...rest }: TextFieldProps) {
  const generatedId = useId()
  const inputId = id ?? generatedId
  const errorId = `${inputId}-error`

  return (
    <label className={styles.field} htmlFor={inputId}>
      <span className={styles.labelRow}>
        {label}
        {labelAction}
      </span>
      <input
        id={inputId}
        ref={ref}
        className={error ? `${styles.input} ${styles.inputError}` : styles.input}
        aria-invalid={error ? true : undefined}
        aria-describedby={error ? errorId : undefined}
        {...rest}
      />
      {error && (
        <span id={errorId} className={styles.error} role="alert">
          {error}
        </span>
      )}
    </label>
  )
}
```

### 5.21 `src/features/auth/schemas/authSchemas.ts` — crear

> Sintaxis de **zod 4** (H2): `z.email()` es top-level y los mensajes van en `error`
> (`errorMap` y `z.string().email()` son API de zod 3). `z.email({ error })` y
> `z.literal(true, { error })` están verificados contra zod 4.5.

```ts
import { z } from 'zod'

const emailField = z.email({
  error: (issue) => (issue.input === '' ? 'Escribe tu correo.' : 'Ese correo no parece válido.'),
})

export const loginSchema = z.object({
  email: emailField,
  password: z.string().min(1, 'Escribe tu contraseña.'),
})

export const registerSchema = z.object({
  name: z.string().trim().min(1, 'Escribe tu nombre.'),
  email: emailField,
  password: z.string().min(8, 'La contraseña necesita al menos 8 caracteres.'),
  acceptedTerms: z.literal(true, { error: 'Acepta los términos y las reglas de custodia.' }),
})

export type LoginFormValues = z.infer<typeof loginSchema>
export type RegisterFormValues = z.infer<typeof registerSchema>
```

### 5.23 `src/features/auth/services/authService.ts` — crear

> **Decisión cerrada:** el backend todavía no existe. El servicio queda con la forma
> definitiva de la llamada (para que cambiar a HTTP real sea sustituir el cuerpo de la
> función) pero **simula** la respuesta. **No inventar endpoints ni instalar `openapi-fetch`**:
> el contrato real se define cuando exista el backend.

```ts
import type { LoginFormValues, RegisterFormValues } from '../schemas/authSchemas'
import type { AuthUser } from '../store/authStore'

/**
 * Genera un handle con el formato que asigna el sistema al registrarse: @trq-XXXX.
 * Provisional: cuando exista el backend, el handle lo devuelve el servidor.
 */
function generateHandle(): string {
  const suffix = Math.random().toString(36).slice(2, 6)
  return `@trq-${suffix}`
}

function delay(ms: number): Promise<void> {
  return new Promise((resolve) => setTimeout(resolve, ms))
}

// TODO(backend): reemplazar por POST /auth/login con openapi-fetch.
export async function login(values: LoginFormValues): Promise<AuthUser> {
  await delay(600)
  return {
    name: values.email.split('@')[0],
    email: values.email,
    handle: generateHandle(),
  }
}

// TODO(backend): reemplazar por POST /auth/register con openapi-fetch.
// La respuesta real DEBE devolver el @usuario asignado, para mostrárselo al usuario.
export async function register(values: RegisterFormValues): Promise<AuthUser> {
  await delay(600)
  return {
    name: values.name,
    email: values.email,
    handle: generateHandle(),
  }
}
```

```tsx
import { describe, it, expect, vi } from 'vitest'
import { render, screen } from '@testing-library/react'
import userEvent from '@testing-library/user-event'
import { QueryClient, QueryClientProvider } from '@tanstack/react-query'
import { AuthPanel, type AuthTab } from './AuthPanel'

function renderPanel(tab: AuthTab = 'login', onTabChange = vi.fn()) {
  const client = new QueryClient({ defaultOptions: { queries: { retry: false } } })
  render(
    <QueryClientProvider client={client}>
      <AuthPanel tab={tab} onTabChange={onTabChange} />
    </QueryClientProvider>,
  )
  return { onTabChange }
}

describe('AuthPanel', () => {
  it('muestra el formulario de login cuando la pestaña es "login"', () => {
    renderPanel('login')
    expect(screen.getByRole('heading', { name: 'Bienvenido de vuelta' })).toBeInTheDocument()
  })

  it('muestra el formulario de registro cuando la pestaña es "register"', () => {
    renderPanel('register')
    expect(screen.getByRole('heading', { name: 'Crea tu cuenta' })).toBeInTheDocument()
    expect(screen.getByLabelText(/Nombre/)).toBeInTheDocument()
  })

  it('avisa al padre cuando se pulsa la otra pestaña', async () => {
    const user = userEvent.setup()
    const { onTabChange } = renderPanel('login')
    await user.click(screen.getByRole('tab', { name: 'Crear cuenta' }))
    expect(onTabChange).toHaveBeenCalledWith('register')
  })

  it('muestra error de validación si el correo no es válido', async () => {
    const user = userEvent.setup()
    renderPanel('login')
    await user.type(screen.getByLabelText(/Correo/), 'no-es-un-correo')
    await user.type(screen.getByLabelText(/Contraseña/), 'algo')
    await user.click(screen.getByRole('button', { name: 'Entrar' }))
    expect(await screen.findByText('Ese correo no parece válido.')).toBeInTheDocument()
  })
})
```

futuro con el backend: `authService.ts` conserva la firma `login(values) → AuthUser` y
`register(values) → AuthUser` con `handle` en la respuesta, que es lo que el handoff exige
del endpoint real. Nada del plan toca archivos fuera de `frontend/`.
